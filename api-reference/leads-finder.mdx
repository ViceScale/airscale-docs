Search for people using person and company filters. This operation uses a `filters` object and zero-based `page` pagination. [Find people](/api-reference/find-people) uses a different `query` model and cursor pagination; their request bodies are not interchangeable.

<Note>
The limit is 5 requests per second per workspace. Each returned lead costs 0.1 credits; empty pages cost zero credits. At least 0.1 credits must be available before searching; credit admission can reserve up to `size × 0.1` credits before the request runs.
</Note>

## Choose filters

At least one non-empty filter other than `searchMode` is required. Include only the criteria you need. The OpenAPI request schema below lists the supported fields.

| Criteria | Fields |
| --- | --- |
| Job titles | `job`, `jobExclude` |
| Companies | `company`, `companyUrl` |
| Person locations | `peopleLocation`, `peopleLocationExclude` |
| Seniority and functions | `seniority`, `seniorityExclude`, `jobFunction`, `jobFunctionExclude` |
| Tenure and experience | `yearsCurrentRole`, `yearsCurrentCompany`, `yearsWorkExperience`, `duration` |
| Skills, languages, certifications | `skills`, `language`, `certification`, and their `Exclude` fields |
| Profile text and badges | `profileKeywords`, `profileKeywordsExclude`, `profileBadge` |
| Company industry, locations, type | `industry`, `hq`, `type`, and their `Exclude` fields |
| Company size, revenue, founding year | `size`, `revenue`, `founded` |
| Company text | `companyKeywords`, `companyKeywordsExclude` |
| Funding | `funding`, `fundingAmount`, `fundingDateMonths` |
| Department metrics | `department`, `growth` |

Use strings or arrays for `job`, `jobExclude`, `company`, `companyUrl`, person locations, and job functions. Other text filters accept strings; separate multiple values with newlines. Each job-function include/exclude input allows at most 300 non-empty values. `searchMode` supports `SMART`, `WORD`, and `STRICT`, defaulting to `SMART`.

Textual tenure examples include `1 to 2 years`, `Less than 1 year`, and `More than 10 years`. Structured `duration` accepts `latestCompany`, `currentCompany`, `previousCompany`, `latestJob`, `currentJob`, `previousJob`, and `total`. Each contains `min`, `max`, or both, with non-negative integer `year` and/or `month` values; months must be 0–11 and the minimum must not exceed the maximum. Structured bounds override the corresponding textual tenure field.

```json Structured tenure example
{
  "filters": {
    "job": ["Founder"],
    "duration": {
      "currentCompany": { "min": { "year": 1 }, "max": { "year": 3 } }
    }
  },
  "page": 0,
  "size": 25
}
```

## Expected filter values

These values apply to `POST /v1/leads-finder` and the `airscale_leads_finder` MCP tool. [Find Companies filter values](/api-reference/find-companies/filter-values) belongs to a different search and does not list Leads Finder values.

Use the identifiers below for preset filters. Include and exclude fields use the same vocabulary. For string fields, separate multiple values with a newline (`\n` in JSON). `jobFunction` and `jobFunctionExclude` also accept arrays, with at most 300 values in each field. Use exact job-function identifiers, such as `business_development`, rather than display labels such as `Business Development`.

<Note>
Some unsupported legacy values can be ignored instead of rejected. A successful response does not confirm that every supplied filter value was applied. Use the values and formats documented here.
</Note>

### Ranges and dates

These fields take strings rather than preset identifiers. Use plain numbers without currency symbols or thousands separators.

| Field | Expected value | Examples |
| --- | --- | --- |
| `size` | Company headcount range; newline-separated ranges are supported | `"11-50"`, `"10000+"` |
| `revenue` | Annual revenue range in USD; newline-separated ranges are supported | `"1000000-10000000"` |
| `founded` | One founding-year range | `"2015-2022"` |
| `fundingAmount` | One last-funding amount range in USD | `"1000000-5000000"` |
| `fundingDateMonths` | Positive integer number of months as a string | `"3"`, `"6"`, `"12"`, `"24"` |
| `yearsCurrentRole` | Current-role tenure in years | `"1 to 2 years"` |
| `yearsCurrentCompany` | Current-company tenure in years | `"3 to 5 years"` |
| `yearsWorkExperience` | Total work experience in years | `"More than 10 years"` |

The tenure presets are `Less than 1 year`, `1 to 2 years`, `3 to 5 years`, `6 to 10 years`, and `More than 10 years`. Custom continuous ranges such as `"2 to 4 years"` are also supported. If you combine tenure ranges, use adjacent ranges without gaps. For month-level bounds, use the structured `duration` fields described above.

The company-size presets are `1-10`, `11-20`, `21-50`, `51-100`, `101-200`, `201-500`, `501-1000`, `1001-2000`, `2001-5000`, `5001-10000`, and `10000+`. Custom numeric ranges are also supported.

## Read results and paginate

The response contains `rows`, `total`, `page`, and `size`. Each row is a nested person record with **snake_case** keys: the name is under `profile` (`profile.first_name`, `profile.last_name`, `profile.headline`), the LinkedIn URL is `link.linkedin`, work history is `position_groups`, and the current employer is `company` (`company.summary.name`, `company.link.domain`). Fields depend on available data, can be `null` or absent, and rows can include fields not listed in the schema. `total` can be `null` when a reliable count is unavailable or company/title correlation removes rows.

`size` defaults to 50 and accepts 1–100. Start at `page: 0` and increment the page while keeping the same filters and size. This operation does not return `next_cursor`. When company and title filters are combined, returned rows are checked for a matching title at the identified company; a page can contain fewer rows after that check, and a short page alone does not establish exhaustion.

After `429`, retry in a later second with bounded exponential backoff. For `503`, retry with increasing delays and a fixed retry limit; contact support if errors persist. Correct invalid filters before retrying `400` responses. Requests larger than 256 KiB return `413`.
