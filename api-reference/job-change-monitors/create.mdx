Create an active monitor for one to 10,000 personal LinkedIn profiles with [Bearer authentication](/api-reference/authentication). All profiles belong to one monitor ID, with one frequency and optional webhook. Each successful request creates a new monitor. If a network failure leaves the result unknown, list or retrieve monitors before retrying so you do not create an unintended duplicate.

<Note>
The `frequency` can be `weekly`, `every_30_days`, or `every_90_days`. If you provide `webhook_url`, store the returned `signing_secret` immediately; it is returned only on the first successful create response.
</Note>

Airschool canonicalizes LinkedIn URLs and preserves each profile's optional `external_id` in later events. Monitoring admission checks the workspace's configured provider, capacity, and credit balance before accepting the monitor.

## Monitor 10,000 profiles

1. Prepare a JSON request with `name`, your chosen `frequency`, an optional `webhook_url`, and a `profiles` array containing 10,000 personal LinkedIn URLs. Each entry can include an `external_id` from your CRM.
2. Send it to `POST /v1/job-change-monitors`. The `202 Accepted` response contains `monitor`, `profiles`, `signing_secret`, and `signing_secret_warning`. Save `monitor.id` and, if a webhook is configured, the one-time `signing_secret`.
3. Use that same ID with [Get a monitor](/api-reference/job-change-monitors/get) to inspect profile statuses and the monitor's check timestamps. Scans run asynchronously and a large scan can take time; `202` confirms acceptance, not scan completion.
4. Keep the same monitor ID, schedule, and webhook for the whole set. After a profile's first successful check establishes its baseline, later employer changes appear in [List job-change events](/api-reference/job-change-monitors/events) and are sent to the configured webhook. Establishing the first baseline does not emit a job-change event.

Monitoring costs **0.1 credit per profile per check**. Budget 1,000 credits for a check of 10,000 profiles. The available frequencies remain weekly, every 30 days, and every 90 days.

## Request size and profile limits

One monitor supports at most **10,000 active profiles**. Create and [Add profiles](/api-reference/job-change-monitors/profiles/add) each accept up to **10,000 profile entries per request**, while the monitor's resulting active count must stay within 10,000.

The complete JSON request body must be at most **8 MiB (8,388,608 bytes)** in UTF-8. A larger body returns `413`. Long URLs, `external_id` values, and JSON formatting all count toward this limit. If your payload is too large, create the monitor with a smaller set, then add the remaining profiles in smaller requests to the same `monitor.id`. You still use one monitor, schedule, and webhook for the full set.

## Verify webhook signatures

Airscale sends `job_change.detected` as a JSON `POST` to `webhook_url`. The request includes `X-Airscale-Event-Id`, `X-Airscale-Timestamp`, and `X-Airscale-Signature: sha256=<hex>`. Compute HMAC-SHA256 with the one-time `signing_secret` over `<timestamp>.<raw request body>`, compare it in constant time, and reject timestamps older than five minutes. Return a 2xx response only after durable handling. Retries keep the same event ID and are deduplicated by Airscale internally.
