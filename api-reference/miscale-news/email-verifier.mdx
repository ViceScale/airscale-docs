Verify one email address through Airscale's deliverability service. The versioned route is the documented API path. The legacy `/email-verifier` path remains available as a compatibility alias.

## Contract summary

<Badge color="blue">POST</Badge> `/v1/email-verifier`

| Property | Value |
| --- | --- |
| Authentication | Bearer Airscale API key |
| Request body | Exactly one `email` field |
| Credit cost | 0.5 credits per valid verification request |
| Execution | Synchronous; may poll the provider for up to 45 seconds |
| Rate limit | No endpoint throttle |

## Request

The body must contain exactly one valid `email` field. The endpoint rejects extra fields, empty values, invalid email syntax, and bodies larger than 16 KiB.

```json
{
  "email": "maya@example.com"
}
```

```bash cURL
curl --request POST \
  --url https://api.airscale.io/v1/email-verifier \
  --header "Authorization: Bearer $AIRSCALE_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"email":"maya@example.com"}'
```

```python Python
import os
import requests

response = requests.post(
    "https://api.airscale.io/v1/email-verifier",
    headers={"Authorization": f"Bearer {os.environ['AIRSCALE_API_KEY']}"},
    json={"email": "maya@example.com"},
    timeout=90,
)
response.raise_for_status()
print(response.json())
```

```javascript Node.js
const apiKey = process.env.AIRSCALE_API_KEY;
const response = await fetch("https://api.airscale.io/v1/email-verifier", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ email: "maya@example.com" }),
  signal: AbortSignal.timeout(90_000),
});

if (!response.ok) throw new Error(`Email verification failed: ${response.status}`);
console.log(await response.json());
```

## Response

A terminal response reports the provider result and `credits_consumed: 0.5`. The provider may return additional fields, which Airscale preserves in the response body.

```json
{
  "email": "maya@example.com",
  "result": "deliverable",
  "credits_consumed": 0.5
}
```

When the provider initially reports `verifying`, Airscale polls the provider's status endpoint without repeating the paid request or charging a second time. If the provider does not reach a terminal result within the polling window, Airscale returns a successful response with `result: "risky"`.

If the initial provider request returns a non-2xx response, Airscale refunds the reserved credits when possible and passes through the provider status and response body. Provider failure can therefore return the provider's status, such as `422`, rather than a normalized `200` response.

## Errors

| Status | Meaning | Action |
| --- | --- | --- |
| `400 Bad Request` | Invalid JSON or email body. | Send exactly one valid `email` field. |
| `401 Unauthorized` | The API key is missing or invalid. | Send a valid workspace API key. |
| `403 Forbidden` | The workspace does not have 0.5 credits available. | Add credits before retrying. |
| `413 Content Too Large` | The request body exceeds 16 KiB. | Send a smaller JSON body. |
| `422 Unprocessable Content` | The provider rejected the verification request and its response was passed through. | Correct the request if indicated and retry. |
| `500 Internal Server Error` | Email verifier provider configuration is unavailable. | Retry after configuration is restored. |
| `502 Bad Gateway` | The provider could not be reached. | Retry with bounded backoff. |
| `503 Service Unavailable` | Authentication, credit settlement, or provider recovery is unavailable. | Retry after the service recovers. |
