Check whether a mobile number is registered on WhatsApp. The check returns a durable operation ID so clients can reconcile a request when a provider response is delayed or lost.

## Contract summary

<Badge color="blue">POST</Badge> `/v1/whatsapp-check`

<Badge color="green">GET</Badge> `/v1/whatsapp-check/operations/{operation_id}`

| Property | Value |
| --- | --- |
| Authentication | Bearer Airscale API key |
| Request body | Exactly one `phone` field |
| Phone format | Strict E.164: `+` followed by 7–15 digits |
| Rate limit | 60 requests per minute per workspace |
| Credit cost | 1 credit for a definitive result |
| Execution | Synchronous check with durable reconciliation |

## Check a phone number

Send exactly one phone field. Do not include spaces, punctuation, or additional fields.

```json
{
  "phone": "+14155550123"
}
```

An `Idempotency-Key` header is optional. When supplied, it must be a UUID generated by your application. Reuse the same key and request body when retrying a request whose response was lost or timed out.

```bash cURL
curl --request POST \
  --url https://api.airscale.io/v1/whatsapp-check \
  --header "Authorization: Bearer $AIRSCALE_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: 5f73072e-1bb5-4f58-845b-4e65e86b74d4" \
  --data '{"phone":"+14155550123"}'
```

```python Python
import os
import requests

response = requests.post(
    "https://api.airscale.io/v1/whatsapp-check",
    headers={
        "Authorization": f"Bearer {os.environ['AIRSCALE_API_KEY']}",
        "Content-Type": "application/json",
        "Idempotency-Key": "5f73072e-1bb5-4f58-845b-4e65e86b74d4",
    },
    json={"phone": "+14155550123"},
    timeout=30,
)
response.raise_for_status()
print(response.json())
```

```javascript Node.js
const apiKey = process.env.AIRSCALE_API_KEY;
const response = await fetch("https://api.airscale.io/v1/whatsapp-check", {
  method: "POST",

```

## Check response

A definitive `200 OK` response includes the operation ID, normalized phone number, WhatsApp result, and one consumed credit.

```json
{
  "operation_id": "5f73072e-1bb5-4f58-845b-4e65e86b74d4",
  "phone": "+14155550123",
  "whatsapp": "yes",
  "credits_consumed": 1
}
```

`whatsapp` is either `yes` or `no`. An unavailable result returns `503` and consumes no credit. When the request cannot be completed definitively, the response includes an `operation_id` and a `202` state that you can reconcile.

## Reconcile an operation

Use the operation ID returned by the check. The lookup must use an API key from the same workspace.

```bash cURL
curl --request GET \
  --url https://api.airscale.io/v1/whatsapp-check/operations/5f73072e-1bb5-4f58-845b-4e65e86b74d4 \
  --header "Authorization: Bearer $AIRSCALE_API_KEY"
```

While processing, the lookup can return:

```json
{
  "operation_id": "5f73072e-1bb5-4f58-845b-4e65e86b74d4",
  "status": "pending"
}
```

The lookup returns a terminal response when the operation is complete:

```json
{
  "operation_id": "5f73072e-1bb5-4f58-845b-4e65e86b74d4",
  "status": "completed",
  "whatsapp": "no",
  "credits_consumed": 1
}
```

`unknown` is also a `202` state and should be reconciled before retrying. A request made without an idempotency key can create a new paid operation if the original response was lost. Use and reuse your own UUID key when retry protection is required.

## Errors

| Status | Meaning | Action |
| --- | --- | --- |
| `400 Bad Request` | Invalid JSON, phone format, operation ID, or idempotency key. | Send exactly one strict E.164 `phone` field and valid UUID values. |
| `401 Unauthorized` | The API key is missing or invalid. | Send a valid workspace API key. |
| `403 Forbidden` | The workspace does not have enough credits. | Add credits before retrying. |
| `404 Not Found` | The operation does not exist in the workspace. | Check the operation ID and workspace key. |
| `409 Conflict` | An idempotency key was reused with different input. | Use the original request body or a new UUID. |
| `429 Too Many Requests` | The workspace exceeded 60 requests in one minute. | Retry after the rate-limit window. |
| `503 Service Unavailable` | The check or its durable operation store is unavailable. | Reconcile the operation ID before retrying. |
