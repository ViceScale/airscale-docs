Search for people using person, role, current-company, and past-experience filters, then page through the matching lead records.

<Note>
The Search and [Count people](#count-matching-people) operations share a limit of 6 requests per second per workspace. Search costs 0.1 credits per returned lead; empty result pages are not charged. Count accepts the same `query` for free.
</Note>

Search returns at most 100 leads per request. When `next_cursor` is not `null`, send it unchanged as `cursor` with the same `query`. Do not derive or edit cursor contents.

After a `429`, wait for the next second and retry with bounded exponential backoff. A failed search or credit-service attempt does not return charged leads.

## Count matching people

Use `POST https://api.airscale.io/v1/find-people/count` to estimate this audience before retrieving leads. Send the same `query` object and Bearer authorization as Find people, with `Content-Type: application/json`. Omit `size` and `cursor`: Count has no pagination fields.

Count is free. It neither reserves nor debits credits and returns only `total`, the number of matching people. It shares the search rate limit above; after a `429`, retry with bounded backoff.

<Accordion title="Count request and response">

```json Count request
{
  "query": {
    "jobTitle": {
      "include": ["Founder"]
    }
  }
}
```

```json Count response
{
  "total": 1250
}
```

</Accordion>

## Combining past-experience filters

All past-experience filters apply to the same prior role. For example, combining `pastJobTitle.include: ["Engineer"]` with `pastCompanyName.include: ["Example Company"]` finds people who worked as an engineer at that company. It does not match someone who was an engineer at another company and held a different role at Example Company.

`pastCompany.location` accepts country names and ISO alpha-2 country codes, just like `location` and `currentCompany.location`.

## Lead fields

`leads` contains public person records. The following fields are common, not a guarantee that every field is present or non-null. Preserve additional public fields your integration needs and tolerate missing values.

| Field | Meaning |
| --- | --- |
| `firstname`, `lastname` | Person's first and last names. |
| `headline`, `description` | Profile headline and description. |
| `profileUrl` | LinkedIn person profile URL. |
| `jobTitle` | Current role title. |
| `jobStartDate` | Current-role start date, for example `03-2024`. |
| `address` | Person location. |
| `companyName` | Current employer name. |
| `companyUrl`, `companyWebsite` | Employer LinkedIn URL and website. |
| `companySize` | Available company headcount. |
| `companyIndustry`, `companyAddress` | Employer industry and location. |

Use `next_cursor` from the response envelope for pagination. Do not construct a cursor from a lead's fields.
