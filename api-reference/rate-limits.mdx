Airscale rate limits are endpoint-specific. Each endpoint can enforce a different request limit and time window, so use the value documented on the endpoint page you are calling.

## Limits by endpoint

All numeric limits below apply per workspace. A shared limit is one combined allowance for the named routes.

| --- | --- |

| [Email finder](/api-reference/email-finder) | 3,000 requests per minute per workspace. |
| [Bulk email finder](/api-reference/email-finder-(bulk)) | 3,000 input items per minute per workspace. |
| [Mobile finder](/api-reference/mobile-finder) | 3,000 requests per minute per workspace. |
| [Personal email](/api-reference/personal-email) | 2,000 requests per minute per workspace. |
| [People URL finder](/api-reference/people-url-finder) | 6 requests per second per workspace. |
| [People profile](/api-reference/extract-people-profile) | 3,000 requests per minute per workspace. |
| [Company profile](/api-reference/extract-company-profile) | 3,000 requests per minute per workspace. |
| [Domain to LinkedIn](/api-reference/domain-to-linkedin) | 180 requests per minute per workspace. |
| [Reverse email](/api-reference/reverse-email) | 25 requests per second per workspace. |
| [Reverse phone](/api-reference/reverse-phone) | 2,000 requests per minute per workspace. |

Find people shares its **6 requests per second** with Count people. Find companies shares its **6 requests per second** with Company filter values. These are separate limits for the two endpoint families.

For bulk email, the allowance counts **input items**, not HTTP requests. An endpoint without a documented numeric limit should not be treated as unlimited; use bounded concurrency and handle `429` responses.

## Handle rate-limit responses

When a request exceeds an endpoint's limit, the API returns `429 Too Many Requests`. Treat the status code as the rate-limit signal; do not depend on an error field or response header unless that endpoint page documents it.

Only retry when the endpoint page says the operation is safe to retry. Use bounded exponential backoff: cap both the maximum delay and the total number of attempts, then surface a persistent `429` to your application.
