title: "Airsearch"
description: "Research the web and return structured answers with Airsearch."

Ask a research question and receive a sourced answer, with optional fields shaped for your application.

## Contract summary

<Badge color="blue">POST</Badge> `/v1/airsearch`

| Property | Value |
| --- | --- |
| Authentication | Bearer API key |
| Execution | Synchronous |
| Rate limit | 300 requests per minute per workspace |
| Request body limit | 256 KiB |
| Airscale credit cost | 1 credit only for `status: "success"`; `not_found` and `timeout` are not charged. |

## Request

Start with a minimal valid request containing only a non-empty `prompt`:

```json
{
  "prompt": "What does Northstar Labs build?"
}
```

Add an optional `schema` when your application needs named output fields:

```json
{
  "prompt": "Find the company name, website, and founding year for Northstar Labs.",
  "schema": {
    "company_name": "string",
    "website": "url",
    "founded_year": "int"
  }
}
```

Send JSON with `Content-Type: application/json`.

## Top-level fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `prompt` | string | Yes | Non-empty research question or instruction. Surrounding whitespace is removed. |
| `schema` | object | No | Maps output field names to type keywords or plain-language descriptions. |

When `schema` is omitted, Airsearch chooses useful fields from the prompt and returns the common response envelope. When it is present, requested keys can be added at the top level, but clients must treat each one as optional and nullable.

## Schema types

Schema keys are your output field names. Values can use a supported keyword or a short plain-language description. These keywords are extraction and format hints; they do not guarantee native JSON scalar types. Structured values are requested as strings and can be `null` when no valid value is available.

| Keyword | Extraction or format hint | Returned structured value |
| --- | --- | --- |
| `string` | Text value | String or null, when present. |
| `text` | Text value | String or null, when present. |
| `url` | Full HTTP or HTTPS URL | String or null, when present; a string without an HTTP scheme is changed to `null`. |
| `email` | Email address | String or null, when present; an invalid email-shaped string is changed to `null`. |
| `number` | Numeric value | Numeric-looking string or null, when present. |
| `int` | Integer number | Integer-looking string or null, when present. |
| `float` | Decimal number | Decimal-looking string or null, when present. |
| `boolean` | Boolean value | Boolean-looking string or null, when present. |
| `date` | Date value | String or null, when present; a string becomes `null` only when it neither begins with a `YYYY-MM-DD` shape nor parses as a date. |
| `phone` | Phone number | Phone-shaped string or null, when present. |

For a domain-specific output, use a description such as `"funding_usd": "Total funding in USD as a number"`.

## Response

A completed request returns `200 OK` with one of three result statuses: `success`, `not_found`, or `timeout`.

| Field | Type | Description |
| --- | --- | --- |
| `status` | string | `success`, `not_found`, or `timeout`. |
| `response` | string or object | Primary answer, or structured fallback data when no narrative is available. |
| Requested schema keys | string or null, when present | Optional top-level fields shaped by the requested schema. |
| `reasoning` | string or null | Concise basis for the returned answer. |
| `sources` | array | Source URLs used for the answer. |
| `confidence_score` | number | Overall confidence from 0 through 1. |
| `certainty_tag` | string | `low`, `medium`, or `high`. |
| `duration_ms` | number | End-to-end request duration in milliseconds. |

## Success and not-found cases

### Success

`success` means Airsearch produced a usable result and costs 1 credit. Requested schema keys may be omitted from a successful response. When present, structured scalar values are a string or `null`; clients must explicitly parse or coerce numeric and boolean strings when native types are required.

```json
{
  "status": "success",
  "response": "Northstar Labs builds workflow automation software.",
  "company_name": "Northstar Labs",
  "website": "https://northstar.example",
  "founded_year": "2024",
  "reasoning": "The company website describes the product and founding date.",
  "sources": [
    "https://northstar.example/about"
  ],
  "confidence_score": 0.94,
  "certainty_tag": "high",
  "duration_ms": 8420
}
```

A successful response can omit requested keys whose values are unavailable. This example omits `website` and `founded_year` instead of inserting them:

```json
{
  "status": "success",
  "response": "Northstar Labs builds workflow automation software.",
  "company_name": "Northstar Labs",
  "reasoning": "The available source supports the company name and product category.",
  "sources": [
    "https://northstar.example/about"
  ],
  "confidence_score": 0.72,
  "certainty_tag": "medium",
  "duration_ms": 7910
}
```

### Not found

`not_found` means the completed research did not produce enough usable data. It returns `200 OK` and is not charged. Empty-result handling can include requested keys as `null`, as shown below.

```json
{
  "status": "not_found",
  "response": "No relevant information found.",
  "company_name": null,
  "website": null,
  "founded_year": null,
  "reasoning": null,
  "sources": [],
  "confidence_score": 0.1,
  "certainty_tag": "low",
  "duration_ms": 6900
}
```

### Soft timeout

`timeout` means a later research stage exhausted its time budget but the request still completed normally. It returns `200 OK` and is not charged. An initial-stage timeout instead returns `504 Gateway Timeout`.

```json
{
  "status": "timeout",
  "response": "No relevant information found.",
  "company_name": null,
  "website": null,
  "founded_year": null,
  "reasoning": null,
  "sources": [],
  "confidence_score": 0,
  "certainty_tag": "low",
  "duration_ms": 150000
}
```

## Errors

| Status | Cause | Recovery |
| --- | --- | --- |
| `400 Bad Request` | Invalid JSON or a missing or empty `prompt`. | Send valid JSON with a non-empty `prompt`. |
| `401 Unauthorized` | The Bearer token is missing or invalid. | Copy the current key from Airscale Settings and update the server-side secret. |
| `403 Forbidden` | The workspace has fewer than 1 credit or credit reservation is rejected. | Add credits, then retry the request. |
| `413 Content Too Large` | The request body exceeds 256 KiB. | Shorten the prompt or schema. |
| `429 Too Many Requests` | The workspace sent more than 300 requests in the current minute. | Retry after the minute window with bounded exponential backoff. |
| `500 Internal Server Error` | Research processing failed or an unexpected worker error occurred. | Retry once with bounded backoff; contact support if the failure repeats. |
| `502 Bad Gateway` | API-key validation is temporarily unavailable. | Retry the same request with bounded backoff. |
| `503 Service Unavailable` | The credit service could not complete reservation. | Retry the same request after the credit service recovers. |
| `504 Gateway Timeout` | The initial research stage timed out. | Use a narrower prompt, then retry. |

## Rate limits and credits

| Rule | Value |
| --- | --- |
| Requests | 300 per minute per workspace. |
| Request body | 256 KiB maximum. |
| Successful result | 1 Airscale credit. |
| `not_found` | No charge. |
| `timeout` | No charge. |
| Error response | No completed result charge. |

Airsearch checks that at least 1 credit is available before research begins. For supported workspace authentication, a reservation is settled only for `success` and is released for `not_found` or `timeout`.

## Examples

<CodeGroup>
```bash cURL
curl --request POST "https://api.airscale.io/v1/airsearch" \
  --header "Authorization: Bearer $AIRSCALE_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "prompt": "Find the company name, website, and founding year for Northstar Labs.",
    "schema": {
      "company_name": "string",
      "website": "url",
      "founded_year": "int"
    }
  }'
```

```javascript Node.js
const response = await fetch("https://api.airscale.io/v1/airsearch", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.AIRSCALE_API_KEY}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    prompt: "Find the company name, website, and founding year for Northstar Labs.",
    schema: {
      company_name: "string",
      website: "url",
      founded_year: "int"
    }
  })
});

console.log(await response.json());
```
</CodeGroup>
