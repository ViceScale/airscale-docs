**Configure your client**

For a header-based client, store the key outside its configuration file. The placeholder below represents a value supplied through your local environment or secret manager; do not paste a real key into this documentation site.

```bash
export AIRSCALE_API_KEY=YOUR_API_KEY
```

<CodeGroup>
```json Claude Code
{
  "mcpServers": {
    "airscale": {
      "type": "http",
      "url": "https://mcp.airscale.io/mcp",
      "headers": {
        "Authorization": "Bearer ${AIRSCALE_API_KEY}"
      }
    }
  }
}
```

```text Client field mapping (conceptual)
Server URL: https://mcp.airscale.io/mcp
Transport: Streamable HTTP

```

```text OAuth client

Authentication: OAuth
API key field: leave empty
```

## Choose OAuth or header authentication

Use **OAuth** when the client supports browser authorization. The client opens Airscale, asks you to approve workspace access, and stores its own connection credentials.

Use an **authorization header** only for a trusted developer client that reads its key from a local environment or secret manager. Send `Authorization: Bearer $AIRSCALE_API_KEY`; never place an API key in MCP tool arguments, prompts, source control, or browser-side code.

For the underlying API-key policy, see [Authentication](/api-reference/authentication).

## Verify the connection for free

After the client lists Airscale tools, make the first test non-billable. Ask:

> Use `airscale_check_credits` to show my current Airscale credit balance. Do not call another tool.

The credit check has no input fields and does not debit credits. If the client cannot find the tool, refresh the MCP connection before testing a paid capability.

## Run asynchronous exports safely

Large people, company, and managed contact-enrichment jobs use an asynchronous lifecycle:

<Steps>
  <Step title="Define a narrow job">
    Validate filters and keep the requested maximum row count as small as the use case allows.
  </Step>
  <Step title="Review and approve spend">
    Read the maximum possible credit cost. Paid export starts require `confirm_credit_spend: true` only after approval.
  </Step>
  <Step title="Start once">
    Keep the returned export identifier. Do not start a duplicate job while the first is still running.
  </Step>
  <Step title="Poll status">
    Use the status tool and respect its suggested polling interval until the job reaches a terminal state.
  </Step>
  <Step title="Retrieve the file">
    Request the file only after the status reports completion, then store it according to your data-handling policy.
  </Step>
</Steps>

## Understand credits and approval

Free tools include the workspace credit check, people count, and company filter-value discovery. Search and enrichment tools charge according to successful results or calls; Airsearch costs 2 credits per call. The catalog states the exact behavior for each tool.

Export-start tools can create larger charges. They fail closed until `confirm_credit_spend` is set to `true`, but that flag is an approval signal—not a substitute for reviewing filters, row limits, and the maximum possible spend.

## Recommended workflow

1. Verify the connection with `airscale_check_credits`.
2. Use a free count or filter-discovery tool when one applies.
3. Run the smallest useful sample and inspect its shape.
4. Refine filters before increasing the requested size.
5. Review credit behavior in the [tool catalog](/mcp/tools).
6. Approve and start paid export work only when the scope is correct.
7. Poll the existing job rather than starting a duplicate.

For endpoint semantics behind core tools, use the [API reference](/api-reference/api-overview).

## Security

- Prefer browser OAuth when the client supports it.
- Keep header credentials in a local environment or secret manager and out of configuration committed to source control.
- Never send an API key as a tool argument or include one in a prompt.
- Review the tool name and proposed arguments before approving a credit-spending action.
- Rotate a key immediately if it is exposed, then update every trusted client that uses it.
- Treat exported contact data according to your organization's access, retention, and deletion policies.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The client cannot authenticate">
    For OAuth, restart the browser authorization flow and confirm that the intended Airscale workspace is selected. For header clients, confirm that the environment value is available to the client process and that the header begins with `Bearer`.
  </Accordion>
  <Accordion title="The Airscale tools do not appear">
    Confirm that the server URL is exactly `https://mcp.airscale.io/mcp`, then disconnect and reconnect the MCP server so the client refreshes its tool list.
  </Accordion>
  <Accordion title="A request reports insufficient credits">
    Run `airscale_check_credits` and reduce the scope before retrying. Do not repeatedly submit the same paid request.
  </Accordion>
  <Accordion title="An export is still running">
    Continue polling the existing export status at the suggested interval. Start a new job only after you know the first job's terminal outcome.
  </Accordion>
</AccordionGroup>
